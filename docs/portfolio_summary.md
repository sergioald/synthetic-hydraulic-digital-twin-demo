# Portfolio summary: Synthetic Hydraulic Digital Twin Demo

## One-line summary

This repository demonstrates a safe, reproducible applied-AI workflow for hydraulic sensor systems using fully synthetic data.

## Why it is useful

Many engineering and research facilities generate valuable sensor data, but real datasets, controls, operational records, and system architectures often cannot be shared publicly. This project shows how the same software ideas can be communicated without exposing confidential information.

The repository is designed to demonstrate capability in:

- synthetic data generation;
- sensor-data validation;
- feature engineering for time-series signals;
- hydraulic and electrical energy estimation;
- anomaly detection;
- digital-twin state classification;
- engineering-style report generation;
- reproducible Python research software.

## What the workflow does

The workflow starts with generated hydraulic-style sensor signals. These include pressures, flow, motor power, motor speed, temperature, load demand, actuator displacement, command signal, and a vibration/audio-like proxy.

The pipeline then performs:

1. **Validation** — checks missing values, ranges, and signal consistency.
2. **Feature engineering** — creates rolling statistics and derived time-series features.
3. **Energy modelling** — estimates hydraulic and electrical energy and a simple efficiency signal.
4. **Anomaly detection** — combines transparent rules with an Isolation Forest baseline.
5. **Twin-state classification** — converts validation, anomaly, and energy signals into interpretable state labels.
6. **Reporting** — writes a Markdown report with run metrics, state counts, event-label counts, warnings, and recommendations.

## What the example output shows

The example report generated by the repository summarises a synthetic run with:

- 4,320 samples;
- validation status `PASS`;
- combined anomaly samples;
- electrical and hydraulic energy estimates;
- mean efficiency estimate;
- digital-twin state counts;
- synthetic event-label counts;
- recommendation text for engineering-style review.

These outputs are not operational recommendations. They are synthetic examples that demonstrate report structure, data flow, and software design.

## Why the project is safe to publish

The repository does not include real facility data, real sensor exports, proprietary control logic, confidential reports, database schemas, real hydraulic parameters, or real facility diagrams.

The system represented here is intentionally abstract. The sensor names and behaviours are illustrative and generated by code. This makes the repository suitable for public demonstration while still showing an applied-AI workflow relevant to engineering monitoring systems.

## What it demonstrates to reviewers

A reviewer can quickly see that the project covers more than a notebook experiment. It includes:

- a Python package under `src/`;
- a command-line entry point;
- configuration-driven execution;
- generated reports;
- example figures;
- unit tests;
- documentation;
- citation metadata;
- clear confidentiality boundaries.

This makes it useful as a portfolio project for roles involving applied AI, digital twins, sensor data, anomaly detection, scientific Python, and research software engineering.

## Current limitations

The project is intentionally a baseline demonstration. It is not a calibrated hydraulic simulator, not a validated condition-monitoring system, and not an operational digital twin.

Current simplifications include:

- synthetic signals are generated from simple assumptions;
- anomaly labels are injected for demonstration;
- the energy model is approximate;
- the classifier logic prioritises explainability over modelling complexity;
- no real facility calibration is attempted.

## Suggested future improvements

Possible next improvements include:
