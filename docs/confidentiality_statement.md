# Confidentiality and publication boundary

This repository is a synthetic public demonstration of applied-AI and digital-twin workflows for sensor-heavy hydraulic systems.

It does **not** contain real FastBlade data, University of Edinburgh code, partner data, proprietary control logic, facility-specific parameters, industrial reports, real hydraulic measurements, real audio signals, real database schemas or confidential information.

All datasets, signals, parameters, operating behaviours, labels, figures and reports in this repository are generated synthetically by code. Any similarity to real systems is illustrative and non-operational.

## Purpose of the boundary

The purpose of this boundary is to make the repository safe for public portfolio, teaching and research-software review while avoiding disclosure of:

- real facility data;
- private partner information;
- confidential test programmes;
- operational control logic;
- internal reports or diagrams;
- real sensor exports;
- safety-relevant thresholds or procedures.

The repository is intended to show software structure and applied-AI reasoning, not to reproduce a real test facility.

## What the repository may include

The repository may include:

- synthetic time-series data generated from public assumptions;
- generic hydraulic-style variable names;
- illustrative operating states and anomaly labels;
- YAML scenario configurations for synthetic events;
- reproducible Python workflows;
- automated tests using synthetic or toy inputs;
- Markdown and HTML reports generated from synthetic data;
- documentation explaining workflow design, validation scope and limitations;
- figures generated from synthetic outputs.

## What the repository must not include

The repository must not include:

- real FastBlade data, diagrams, images or operating records;
- real University of Edinburgh internal code;
- partner or industrial datasets;
- raw facility sensor exports;
- real operating parameters;
- proprietary control logic;
- facility-specific layouts;
- real acoustic or audio measurements;
- confidential database schemas;
- internal reports, slides or meeting notes;
- private file paths, credentials, usernames, tokens or access details;
- material copied from internal or restricted documents.

## Data and model boundary

This public repository uses generated synthetic data only. It does not require external private data or model artefacts to run the public examples.

If a private research workflow is ever derived from this repository, private data, trained models, calibration files and generated operational reports should remain outside the public Git repository. They should be handled through the relevant institutional, project or partner data-management processes.

## Generated-output boundary

Generated CSV, Markdown and HTML outputs are reproducible demonstration artefacts. They should normally remain untracked unless they are intentionally included as small examples, documentation assets or release artefacts.

Before committing generated outputs, check that they do not contain:

- real sensor values;
- private timestamps;
- real file paths;
- real facility names beyond generic documentation statements;
- partner identifiers;
- confidential notes;
- screenshots of restricted systems.

## Reporting boundary

Reports generated by this repository are synthetic demonstration reports. They may include:

- state counts;
- synthetic event-label counts;
- validation messages;
- energy summaries;
- anomaly counts;
- recommendation text.

These reports must not be interpreted as real operating reports, real maintenance recommendations or safety-critical diagnostics.

## Recommended pre-commit confidentiality check

Before publishing or pushing changes, run:

```bash
git status
pre-commit run --all-files
pytest
```

Then manually review any newly added files. Useful search commands include:

```bash
git grep -n "password"
git grep -n "token"
git grep -n "secret"
git grep -n "C:\\"
git grep -n "/Users/"
git grep -n "confidential"
```

The search results require judgement. Some documentation may intentionally use words such as `confidential` to explain the boundary.

## Intended use

The repository is intended for:

- public portfolio demonstration;
- research-software review;
- teaching and method discussion;
- demonstration of applied-AI workflow structure;
- demonstration of synthetic sensor validation, anomaly detection, state classification and reporting.

## Out-of-scope use

The repository is not intended for:

- operational monitoring;
- real-time control;
- safety-critical decisions;
- real fault diagnosis;
- validating the health of a real hydraulic system;
- reproducing confidential industrial or research outputs.

## Maintenance rule

When adding new functionality, documentation, figures, reports or examples, maintain the same boundary:

> public code and synthetic examples are acceptable; real or confidential project material is not.
